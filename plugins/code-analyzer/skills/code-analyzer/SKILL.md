分析游戏项目代码架构与实现，自动生成审查文档。

## 工作流程

1. **提取参数** - 从用户提示中提取：
   - 目标代码路径
   - 分析需求描述（用于目录命名）

2. **调用负责人** - 使用 `analysis-leader` agent 执行分析：
   - 传递目标路径、分析描述
   - 负责人自动识别领域、调度专家、生成汇总

## 输出结构

```
./docs/
└── {日期}-{分析需求提要}/
    ├── summary.md          # 总概括文档（含综合评分）
    ├── architecture.md     # 各领域专家生成
    ├── rendering.md
    ├── network.md
    └── ...
```

**目录命名**：`{日期}-{分析需求提要}`
- 示例：`2026-03-19-渲染模块审查/`

## 评分体系

**各专家评分**（5个维度，1-10分）：
- 维度根据领域特点定制
- 计算领域综合评分（平均值）

**汇总评分**（summary.md）：
- 各领域综合评分表
- 项目总体评分（加权平均）
- 评分分布统计
- 雷达图数据（JSON格式）

**评分等级**：
| 分数 | 等级 | 说明 |
|------|------|------|
| 9-10 | ⭐⭐⭐⭐⭐ 卓越 | 业界领先水平 |
| 7-8 | ⭐⭐⭐⭐ 良好 | 质量较高 |
| 5-6 | ⭐⭐⭐ 一般 | 基本可用 |
| 3-4 | ⭐⭐ 较差 | 需要重构 |
| 1-2 | ⭐ 需重构 | 严重影响项目 |

## 可用领域

负责人自动根据路径和描述选择需要的领域：

| 领域 | 标识 | 关注点 |
|------|------|--------|
| 架构 | architecture | 整体架构、模块划分、设计模式 |
| UI框架 | ui | UI架构、事件系统、布局动画 |
| 渲染管线 | rendering | 渲染架构、Shader、光照优化 |
| 网络同步 | network | 帧同步、状态同步、预测回滚 |
| 场景管理 | scene | 场景图、流式加载、大世界 |
| 对象管理 | object | ECS、对象池、序列化 |
| 物理引擎 | physics | 碰撞检测、刚体、角色控制 |
