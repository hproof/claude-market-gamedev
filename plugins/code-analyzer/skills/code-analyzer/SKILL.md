启动代码审计工作流，协调多阶段分析过程。

## 工作流程

1. **提取参数**
   - 目标代码路径（默认为当前目录 `.`）
   - 分析需求描述（可选，用于命名输出目录）

2. **Phase 1: 初步扫描**
   - 调用 `master-analyzer` agent 进行项目整体扫描
   - 按目录内聚性识别模块
   - 输出模块结构文档

3. **Phase 2: 模块分析**
   - 创建 `thirdparty-analyzer` 分析所有第三方库
   - 为每个底层模块创建 `module-analyzer`（并发数最多3个）
   - 创建 `business-analyzer` 分析业务层（区分场景内/无关）

4. **Phase 3: 汇总报告**
   - 收集各模块分析结果
   - 生成综合审计报告

## 模块识别规则

- **第三方库**：third_party/ 等目录下的外部依赖
- **底层模块**：提供通用能力的核心模块（全部分析，并发最多10个）
- **业务模块**：
  - 场景内业务：战斗、探索等（与场景绑定）
  - 场景无关业务：背包、强化等（UI交互）

## 输出结构

```
./docs/
└── {日期}-{时间}-{分析需求提要}/
    ├── 00-project-overview.md     # 项目整体结构
    ├── 01-thirdparty.md           # 所有第三方库分析
    ├── 02-mod-{模块名}.md         # 底层模块分析（全部，并发最多3个）
    ├── 03-business.md             # 业务层分析（场景内+无关）
    └── summary.md                 # 汇总报告
```

## 使用示例

```
/code-analyzer ./src 战斗系统审查
/code-analyzer . 整体架构评估
```
