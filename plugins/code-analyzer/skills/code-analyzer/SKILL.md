# code-analyzer

分析游戏项目代码实现方案，输出分析文档。可指定整体工程或特定模块，支持多领域专家分析。

## 使用方法

```
/code-analyzer <目标路径> [选项]
```

### 参数

- `目标路径` - 要审查的代码目录或文件路径（必需）
- `--expert, -e` - 指定审查专家（可多选）
  - `architecture` - 架构专家
  - `ui` - UI框架专家
  - `rendering` - 渲染管线专家
  - `network` - 网络同步专家
  - `scene` - 场景管理专家
  - `object` - 对象管理专家
  - `physics` - 物理引擎专家
  - `all` - 所有专家（默认）
- `--output, -o` - 输出目录（默认为 `docs/`）
- `--name, -n` - 文档名称前缀（默认为模块名）

### 示例

```
# 分析整个项目（所有专家）
/code-analyzer ./src

# 仅分析渲染模块
/code-analyzer ./src/renderer -e rendering

# 分析网络和场景模块
/code-analyzer ./src -e network,scene

# 指定输出目录和名称
/code-analyzer ./src/network -e network -o ./reviews -n network-module
```

## 工作流程

1. **分析目标路径** - 识别代码类型和模块结构
2. **选择审查专家** - 根据参数启动对应的 Agent
3. **并行审查** - 多个专家同时分析各自领域
4. **生成报告** - 每个专家输出独立的 Markdown 审查文档
5. **汇总索引** - 生成汇总索引文档

## 输出文档

所有文档保存到指定输出目录（默认为 `docs/`），命名格式：

```
[日期时间]-[领域]-[模块范围].md

示例：
- 2026-03-19-103045-architecture-core.md      # 核心模块架构分析
- 2026-03-19-103122-rendering-shader.md        # 着色器渲染分析
- 2026-03-19-103158-network-sync.md            # 同步模块网络分析
- 2026-03-19-103205-physics-full.md            # 完整物理引擎分析
```

## 专家领域说明

### architecture（架构专家）
评审整体架构设计、模块划分、依赖关系、设计模式、可扩展性。

### ui（UI框架专家）
评审UI架构、事件系统、布局系统、动画系统、资源管理。

### rendering（渲染管线专家）
评审渲染架构、材质/Shader系统、光照、后处理、渲染优化。

### network（网络同步专家）
评审帧同步/状态同步、预测回滚、网络优化、安全性。

### scene（场景管理专家）
评审场景图、空间分区、流式加载、场景切换、大世界支持。

### object（对象管理专家）
评审ECS架构、对象生命周期、对象池、序列化、引用管理。

### physics（物理引擎专家）
评审碰撞检测、刚体动力学、约束求解、角色控制、物理优化。

## 实现说明

当调用此 skill 时，会执行以下操作：

1. 解析参数确定目标路径和审查专家
2. 为每个选定的专家创建独立的 Agent 会话
3. 并行执行各领域的代码审查
4. 收集各专家的审查报告
5. 生成汇总索引文档

**注意**：
- 大型项目审查可能需要较长时间
- 建议在 `.claudeignore` 中排除不必要的目录（如第三方库、构建产物）
- 审查报告包含源代码行号链接，可在 VS Code 中直接点击跳转
