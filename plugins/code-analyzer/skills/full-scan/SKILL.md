执行项目整体代码扫描，识别模块分布并生成项目结构文档。

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `scope` | string | 否 | 分析范围（目录路径），默认为当前目录 `.` |
| `output_file` | string | 否 | 输出文件路径，由调用方指定 |

## 工作流程

1. **扫描项目结构**
   - 读取 `.claudeignore` 文件，获取忽略规则（如存在）
   - 遍历目录树，跳过被忽略的文件和目录
   - 识别目录类型（第三方/底层/业务）
   - 分析模块间依赖关系

2. **模块识别与分类**

   **第三方库识别**：
   - 扫描 `third_party/`、`external/`、`libs/`、`vendor/` 等目录
   - 识别开源许可证文件（LICENSE、COPYING）

   **底层模块识别**：
   - 被业务模块依赖但很少依赖业务模块
   - 提供通用能力（渲染、网络、音频、资源管理等）
   - 目录内语言一致、功能内聚

   **业务模块识别**：
   - 场景内业务：战斗、探索等（与场景绑定）
   - 场景无关业务：背包、强化等（UI交互）

3. **生成项目概览文档**
   - 输出到指定的 `output_file`
   - 包含模块分布图、依赖关系图

## 模块识别规则

### 内聚性判断
- 目录下语言一致、功能相关 → 视为一个模块
- `utils` 处理：不单独作为模块，归入父模块分析
- 混合语言：单个模块内不应混合语言，如遇则视为多个模块
- 大型模块：初审识别为粗粒度模块，内部子模块后续分析

### 第三方库（Third-Party）

识别特征：
- 位于 `third_party/`、`external/`、`libs/`、`vendor/` 等目录
- 包含开源许可证文件（LICENSE、COPYING）
- 版本号文件或变更日志

### 底层模块（Core/Infra Modules）

识别特征：
- 被业务模块依赖但很少依赖业务模块
- 提供通用能力（渲染、网络、音频、资源管理等）
- 目录内语言一致、功能内聚

### 业务模块（Business Modules）

识别特征：
- 实现具体游戏功能（战斗、背包、任务等）
- 依赖底层模块提供的能力
- 代码量大、逻辑复杂

**业务类型划分**：
- **场景内业务**：玩家进入场景后的玩法（战斗、探索等）
- **场景无关业务**：包裹操作、道具强化、社交等

## `.claudeignore` 处理规则

- 如目标路径下存在 `.claudeignore` 文件，读取并解析其中的忽略规则
- 支持标准 `.gitignore` 格式（通配符 `*`、`**`、否定规则 `!` 等）
- 被忽略的目录在扫描时完全跳过（包括子目录）
- 被忽略的文件不参与模块识别和统计

## 输出规范

**输出文件**：由调用方通过 `output_file` 参数指定

示例：`./docs/code-analyzer/root-full-scan.md`
