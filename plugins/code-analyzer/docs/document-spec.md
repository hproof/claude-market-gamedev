# 文档生成规范

本文档定义 code-analyzer 生成的分析文档的格式规范。

## 1. 文档命名规范

### 固定输出目录

所有分析文档保存到：**`./docs/code-analyzer/`**

### 文档命名规则

文档名由 **分析范围 + 分析类型** 组成：

```
{normalized-scope}-{type}.md
```

### 范围路径标准化

| 原始路径 | 标准化后 |
|----------|----------|
| `.` | `root` |
| `./src` | `src` |
| `./src/render` | `src-render` |
| `./game/battle` | `game-battle` |
| `/home/project/src` | `home-project-src` |

**标准化规则：**
1. 移除前导 `./` 或 `/`
2. 将路径中的 `/` 替换为 `-`
3. 空路径（即 `.`）转换为 `root`

### 命名示例

| 分析范围 | 分析类型 | 文档名 |
|----------|----------|--------|
| `.` | `full-scan` | `root-full-scan.md` |
| `./src` | `structure` | `src-structure.md` |
| `./src/render` | `flow` | `src-render-flow.md` |
| `./game/battle` | `flow` | `game-battle-flow.md` |

## 2. 文档结构规范

### 头部模板

每个文档必须以以下结构开头：

```markdown
# {文档标题}

> [返回 Manifest](./manifest.md)

## 导航

| 章节 | 链接 |
|------|------|
| {章节1} | [#1-{章节1}](#1-{章节1}) |
| {章节2} | [#2-{章节2}](#2-{章节2}) |
| ... | ... |
```

### 章节规范

根据分析类型，文档应包含以下章节：

**full-scan（整体扫描）：**
1. 项目概览
2. 模块分布
3. 模块层级图
4. 依赖关系
5. 后续分析建议

**structure（结构分析）：**
1. 目录结构
2. 类关系图
3. 模块依赖
4. 问题与建议

**flow（流程分析）：**
1. 初始化流程
2. 主循环流程
3. 网络同步流程
4. 关键业务流程
5. 问题与建议

### 底部模板

每个文档必须以以下结构结尾：

```markdown
---
*生成时间: {YYYY-MM-DD HH:MM}*

[↑ 返回导航](#导航)
```

## 3. 表格使用规范

### 常用表格格式

**属性表：**
```markdown
| 属性 | 值 |
|------|-----|
| 名称 | {value} |
| 路径 | `{path}` |
```

**列表表：**
```markdown
| 序号 | 名称 | 说明 |
|------|------|------|
| 1 | {name} | {desc} |
```

**问题表：**
```markdown
| 严重程度 | 问题 | 位置 | 建议 |
|---------|------|------|------|
| 高/中/低 | {desc} | `[位置](path:line)` | {suggestion} |
```

**评分类：**
```markdown
| 维度 | 评分(1-10) | 说明 |
|------|-----------|------|
| {维度} | x | {说明} |
```

## 4. 图表规范

### 层级图

使用 ASCII 艺术表示层级关系：

```markdown
```
[顶层]
  ├── [子层1]
  │     ├── [子子层1]
  │     └── [子子层2]
  └── [子层2]
```
```

### 依赖图

使用箭头表示依赖关系：

```markdown
```
[模块A] ──▶ [模块B] ──▶ [模块C]
   │                        ▲
   └────────────────────────┘
```
```

### 流程图

使用箭头表示执行流程：

```markdown
```
[开始]
  ├── [步骤1]
  ├── [步骤2]
  └── [结束]
```
```

## 5. 文档覆盖规则

当执行相同分析时（相同的 scope 和 type）：

1. **覆盖旧文档**：新生成的文档直接覆盖旧文档
2. **更新 Manifest**：在 manifest.md 中更新时间戳和简要说明
3. **保留历史**：如需保留历史版本，手动备份旧文档

## 6. 文档关联

### 引用其他分析文档

在文档中引用其他分析结果时，使用相对路径：

```markdown
详细结构分析见 [src-structure.md](./src-structure.md)
渲染流程分析见 [src-render-flow.md](./src-render-flow.md)
```

### 引用 Manifest

每个文档顶部必须包含返回 Manifest 的链接：

```markdown
> [返回 Manifest](./manifest.md)
```
