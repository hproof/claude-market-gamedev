# 评分标准指南

本文档定义 code-analyzer 的评分维度和标准。

## 1. 评分维度

### 通用维度（所有分析类型）

| 维度 | 说明 | 评估要点 |
|------|------|----------|
| **可读性** | 代码易于理解的程度 | 命名规范、注释质量、代码组织 |
| **可维护性** | 代码易于修改的程度 | 模块化程度、耦合度、复杂度 |
| **正确性** | 代码实现正确的程度 | 逻辑正确、边界处理、错误处理 |

### 结构分析专用维度

| 维度 | 说明 | 评估要点 |
|------|------|----------|
| **目录组织** | 目录结构的合理性 | 层级深度、职责分离、命名规范 |
| **类设计** | 类设计的质量 | 单一职责、继承合理、接口清晰 |
| **依赖管理** | 模块依赖的健康度 | 无循环依赖、依赖方向正确 |

### 流程分析专用维度

| 维度 | 说明 | 评估要点 |
|------|------|----------|
| **流程清晰度** | 执行流程的清晰程度 | 步骤明确、职责分离、易于追踪 |
| **性能** | 流程执行的性能 | 无冗余操作、优化合理、资源管理 |
| **健壮性** | 流程的容错能力 | 错误处理、状态恢复、边界处理 |

### 模块分析专用维度

| 维度 | 说明 | 评估要点 |
|------|------|----------|
| **接口设计** | 公开接口的设计质量 | 清晰、易用、稳定 |
| **内聚性** | 模块职责的集中程度 | 单一职责、功能相关 |
| **耦合度** | 模块间的依赖程度 | 松耦合、依赖明确 |
| **实现质量** | 代码实现的质量 | 算法选择、代码简洁、无冗余 |
| **可测试性** | 模块易于测试的程度 | 可隔离、可Mock、测试覆盖 |

## 2. 评分标准（1-10分）

| 分数 | 等级 | 含义 | 行动建议 |
|------|------|------|----------|
| 9-10 | ⭐⭐⭐⭐⭐ 卓越 | 业界领先水平，可作为标杆 | 保持现状，可作为最佳实践分享 |
| 7-8 | ⭐⭐⭐⭐ 良好 | 质量较高，少量优化空间 | 小幅优化，持续改进 |
| 5-6 | ⭐⭐⭐ 一般 | 基本可用，有明显改进空间 | 制定改进计划，逐步优化 |
| 3-4 | ⭐⭐ 较差 | 存在较多问题，需要重构 | 优先重构，投入资源改进 |
| 1-2 | ⭐ 需重构 | 严重影响项目，必须优先处理 | 立即重构，阻断风险 |

## 3. 各等级详细定义

### 卓越（9-10分）

**特征：**
- 设计优雅，符合最佳实践
- 代码清晰，自解释性强
- 扩展性好，易于维护
- 性能优良，资源管理得当

**示例：**
- 命名准确反映意图
- 函数短小精悍（<20行）
- 模块职责单一明确
- 依赖关系清晰无循环

### 良好（7-8分）

**特征：**
- 整体设计合理
- 代码可读性良好
- 少量可改进之处
- 满足当前需求

**示例：**
- 命名基本清晰，偶有模糊
- 函数长度适中（<50行）
- 模块职责基本单一
- 依赖关系基本合理

### 一般（5-6分）

**特征：**
- 设计存在一些问题
- 代码可读性一般
- 有一定技术债务
- 需要改进计划

**示例：**
- 命名不够准确，需要注释辅助
- 函数较长（>50行）
- 模块职责不够单一
- 存在少量循环依赖

### 较差（3-4分）

**特征：**
- 设计存在明显问题
- 代码难以理解
- 技术债务严重
- 影响开发效率

**示例：**
- 命名模糊，无注释
- 函数过长（>100行）
- 模块职责混乱
- 循环依赖严重

### 需重构（1-2分）

**特征：**
- 设计严重不合理
- 代码难以维护
- 存在严重风险
- 阻碍项目进展

**示例：**
- 命名与实现不符
- 函数过长且逻辑混乱
- 模块职责严重不单一
- 架构设计错误

## 4. 综合评分计算

### 简单平均法

```
综合评分 = Σ(各维度评分) / 维度数量
```

### 加权平均法（可选）

```
综合评分 = Σ(维度评分 × 权重) / Σ权重
```

**推荐权重（模块分析）：**
| 维度 | 权重 |
|------|------|
| 接口设计 | 20% |
| 内聚性 | 20% |
| 耦合度 | 20% |
| 实现质量 | 25% |
| 可测试性 | 15% |

## 5. 评分表示例

### 模块分析评分表

```markdown
## 综合评分

| 维度 | 评分(1-10) | 说明 |
|------|-----------|------|
| 接口设计 | 7 | 接口基本清晰，个别命名可优化 |
| 内聚性 | 8 | 职责单一，功能内聚 |
| 耦合度 | 6 | 与3个模块有依赖，1处可优化 |
| 实现质量 | 7 | 实现良好，少量冗余代码 |
| 可测试性 | 6 | 部分函数可测试性较差 |

**模块综合评分：6.8/10** ⭐⭐⭐

**评价：** 整体质量良好，耦合度和可测试性有改进空间。
```

## 6. 评分注意事项

1. **客观公正**：基于代码实际情况评分，避免主观偏见
2. **有据可依**：每个评分都应有具体代码位置支撑
3. **区分维度**：不同维度独立评分，避免以偏概全
4. **提供建议**：低分维度必须提供具体改进建议
5. **动态调整**：随着代码改进，评分应相应更新
