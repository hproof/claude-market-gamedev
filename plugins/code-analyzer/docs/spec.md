# Code Analyzer 共用规范

所有分析 Skill 生成文档时共同遵守的规范。

## 1. 文档结构

### 头部（必须）

```markdown
# {文档标题}

> [返回 Manifest](./manifest.md)

## 导航

| 章节 | 链接 |
|------|------|
| {章节1} | [#1-{章节1}](#1-{章节1}) |
```

### 章节末尾

每个章节末尾添加返回导航链接：

```markdown
[↑ 返回导航](#导航)
```

### 底部（必须）

```markdown
---
*生成时间: {YYYY-MM-DD HH:MM}*

[↑ 返回导航](#导航)
```

### 文档间引用

使用相对路径：`[src-structure.md](./src-structure.md)`

## 2. 代码链接格式

```markdown
[显示文本](file_path:line_number)
```

- 使用相对于项目根目录的路径，不含前导 `./`
- 统一使用正斜杠 `/`（包括 Windows）
- 行号从 1 开始，可用范围格式 `path:45-78`

| 类型 | 格式 | 示例 |
|------|------|------|
| 方法 | `ClassName::Method` | `[GameManager::Init](src/manager.cpp:45)` |
| 函数 | `FunctionName` | `[LoadConfig](src/config.cpp:23)` |
| 类 | `ClassName` | `[GameObject](src/object.h:15)` |
| 成员 | `ClassName::member` | `[GameManager::m_render](src/manager.h:34)` |

## 3. 评分标准

### 通用维度（所有分析类型）

| 维度 | 评估要点 |
|------|----------|
| **可读性** | 命名规范、注释质量、代码组织 |
| **可维护性** | 模块化程度、耦合度、复杂度 |
| **正确性** | 逻辑正确、边界处理、错误处理 |

### 评分等级（1-10 分）

| 分数 | 等级 | 含义 |
|------|------|------|
| 9-10 | 卓越 | 业界领先，可作为标杆 |
| 7-8 | 良好 | 质量较高，少量优化空间 |
| 5-6 | 一般 | 基本可用，有明显改进空间 |
| 3-4 | 较差 | 存在较多问题，需要重构 |
| 1-2 | 需重构 | 严重影响项目，必须优先处理 |

### 评分要求

- 基于代码实际情况，有据可依
- 各维度独立评分，低分维度必须提供具体改进建议
- 综合评分 = 各维度评分的平均值

### 评分表格式

```markdown
| 维度 | 评分(1-10) | 说明 |
|------|-----------|------|
| {维度} | x | {说明} |

**综合评分：x.x/10**
```

## 4. 常用表格格式

**问题表：**

```markdown
| 严重程度 | 问题 | 位置 | 建议 |
|---------|------|------|------|
| 高/中/低 | {desc} | `[位置](path:line)` | {suggestion} |
```

**属性表：**

```markdown
| 属性 | 值 |
|------|-----|
| 名称 | {value} |
| 路径 | `{path}` |
```

## 5. 图表规范

使用 ASCII 艺术：

```
[顶层]
  ├── [子层1]
  │     ├── [子子层1]
  │     └── [子子层2]
  └── [子层2]
```

依赖方向用箭头：`[模块A] ──▶ [模块B]`
